# 跨包近重复收敛

≥2 个 packages/apps 中行为几乎相同或仅有微差时：先判定关系，再决定收敛或保留分叉。单包内整理不在范围。

## 判定关系（三选一）

比**契约**（入参、出参、失败行为），不要只比代码长相。

| 关系 | 含义 | 动作 |
|------|------|------|
| **同契约** | 契约相同，实现可互换 | 保留一处权威实现；他处改为依赖或删除 |
| **无意漂移** | 本应同契约，复制后各自改动不一致 | 选定权威语义并统一；删除副本 |
| **有意分叉** | 差异对应不同不变量或不同层职责，且能说明 | 保留；不同名称与注释标清差异 |

## 微小差异

| 情况 | 处理 |
|------|------|
| 无业务理由（命名、写法、漏改边界） | 按同契约或无意漂移收敛 |
| 有理由且可参数化，不模糊职责 | 收敛为一个带明确参数的实现 |
| 有理由，参数化会揉进两层职责 | 有意分叉 |

## 收敛落点（按序）

须同时满足 [package-roles](./package-roles.md)、[dependency-dag](./dependency-dag.md)。

1. 某包已有同契约公开 API，且依赖边合法 → 他包 import，删本地副本。
2. 否则按 package-roles 放入职责包并导出 → 他包依赖之。
3. 仅当满足 [utils-admission](./utils-admission.md)（硬条件 + A/B/C）→ 抽入 `utils`；否则停在 2 或保持有意分叉。

权威实现确定后：副本测试删除，或改为只测适配/调用；不得为去重引入逆层、循环，或把业务语义塞进 utils。

## 禁止

- ❌ 无限期保留无意漂移（「以后再统一」）
- ❌ 把有意分叉硬合并成一个模糊 API
